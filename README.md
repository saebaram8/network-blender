# 만남 배분기

2박 3일 워크샵에서 **세션마다 조를 다시 짜서, 사람들이 될수록 많은 사람을 새로 만나게** 하는 도구.
숙박 방배정까지 함께 낸다.

`index.html` **한 파일**이 전부다. 서버도, 통신도, 외부 라이브러리도 없다.
브라우저에서 그냥 열면 되고, 인터넷이 끊긴 워크샵장에서도 돈다.
배정은 전부 브라우저 안에서 계산하므로 **몇 번을 다시 돌려도 비용이 들지 않는다.**

## 쓰는 법

1. 구글 스프레드시트에서 명단을 범위 지정해 복사한다
2. 페이지 **아무 데서나 `Ctrl`+`V`** — 첫 줄은 열 이름으로 읽는다
3. 세션마다 **무엇을 고르게 섞을지** 고른다 (무시 / 보통 / 중요 / 필수)
4. 배정표·숙박표가 곧바로 나온다. `결과 복사` 로 시트에 되붙인다

명단 예:

| 이름 | 성별 | 소속 | 일행 | 개발경험 | 사전교육 |
|---|---|---|---|---|---|
| 정철인 | 남 | 가온 |  | 있음 | 수료 |
| 서연 | 여 | 나루 | A | 없음 | 미수료 |

**열 이름은 아무거나 좋다.** 이름·일행·성별처럼 생긴 열은 알아서 짚고,
나머지 열은 전부 "섞을 조건" 후보가 된다. 틀리게 짚었으면 드롭다운으로 고치면 된다.

## 어떻게 굴러가나

### 지키는 것

- **일행은 같은 조에 들지 않는다** — `일행` 열의 값이 같은 사람끼리. 벌점 2000 으로 사실상 하드다.
  다만 **묶음 하나가 조 개수보다 크면 산수로 못 가른다** — 그때는 진단이 그렇게 말해준다.
  명단 화면에 `일행: N묶음 · M명` 이 늘 떠 있다. 여기가 `열이 정해지지 않았습니다` 면
  일행 열을 못 짚은 것이고, 그러면 아무 제약 없이 섞인다
- **숙박은 동성끼리, 2인실** — `같은 방으로 묶기` 만 예외다
- **조 크기 차이는 한 명 이내**

### 값을 매겨 고르는 것

배정은 아래 값을 다 더해 가장 싼 자리를 찾는다(담금질, simulated annealing).
씨앗을 고정하므로 **같은 조건이면 늘 같은 결과**가 나온다.

| 무엇 | 값 |
|---|---|
| 이미 만난 사이를 또 같은 조에 | 만난 횟수² × (0·1·3·10) |
| 일행이 같은 조에 | 400 |
| 조건 값이 조마다 치우침 | (실제 − 이상)² × (0·1·4·20) |
| 사람마다 같은 조에 앉는 자리 수가 벌어짐 | (자리 수)² × 0.5 |
| 값이 기울인 몫에서 벗어남 | (실제 − 기울인 몫)² × 20 |
| 불리한 사람만 있고 도울 사람이 없는 조 | 60 |

네 번째가 **기회 균등**이다. 조 크기가 들쭉날쭉하면 누구는 큰 조만 만나
남보다 많은 사람을 만난다 — 적게 앉은 사람을 큰 조로 보내 그것을 메운다.
유·불리를 정한 세션에서는 이 항을 끈다. 둘 다 조 크기를 밀면 서로 상쇄한다.

### 조 크기로 메우기 (해커톤)

코딩을 못 하는 사람은 **손이 많은 조**로, 잘하는 사람은 **손이 적은 조**로 보낸다.
세션 카드의 `조 크기로 메우기` 에서 값을 눌러 정한다 — **큰 조 ▸ 작은 조 ▸ 안 봄** 으로 돈다.

`O / X` · `○ / ×` · `있음 / 없음` · `수료 / 미수료` · `가능 / 불가` 를 알아서 짚고(`biasGuess`),
`?` 는 **불리 쪽**으로 본다 — 모르는 사람을 큰 조에 넣어 틀려도 손해가 없다.

값이 대체로 숫자면 **척도**로 읽는다(`scaleBias`): 제일 낮은 값이 불리, 제일 높은 값이 유리,
가운데는 비례. `3 전문 개발자 / 2 바이브 코딩 가능 / 1 경험 없음` 같은 실력 등급이 여기 걸린다.

**유·불리를 정한 열은 그 열의 모든 값에 목표를 준다.** `+1` 값만 잡으면 나머지가 자유로워져,
1 만 흩어지고 2 와 3 이 뭉친다. 부호 0 인 값은 그냥 비례 몫이다 — 그래서 `O` 나 `?` 처럼
우리가 임의로 넣은 값도 조마다 고르게 퍼진다.

### 불리함이 누적되지 않게

조 크기로 메우는 것만으로는 모자란다. `1` 이 둘인데 `3` 이 하나도 없는 조가 나올 수 있고,
그 조의 `1` 은 큰 조에 갔다는 것 말고는 아무 도움을 못 받는다.
**불리한 사람이 있는 조에는 유리한 사람이 적어도 하나 있어야 한다**(`HELP_PEN` 60).
유리한 값이 아예 없는 명단에서는 지킬 수 없으니 그때는 이 항을 끈다.

조 카드에 `▲1 1 · ▼3 2` 처럼 양쪽이 다 뜬다 — 도울 사람이 있는지 눈으로 보인다.

**선형으로 밀고 이차로 막는 짝은 쓰지 않는다.** 같은 열에 걸린 `필수` 분산(20)이 비례 쪽으로
더 세게 당겨서 선형 항이 묻힌다. 대신 **목표 자체를 기울인다** — 조의 몫을 인원 `L` 이 아니라
`L + 2·(L − 평균)` 으로 잡는다. 가중치의 합이 `n` 이라 목표의 합은 언제나 전체 인원수다.

이차라 몰림은 여전히 막히고, 목표가 큰 조 쪽에 가 있으니 방향은 확실하다.
29명·6조(5,5,5,5,5,4)에서 X 16명이면 **5인조 2.9명 · 4인조 1.3명**이 목표다
(비례로만 두면 2.8 · 2.2 라 차이가 거의 없다). 실측: 5인조 X 3명씩, 4인조 X 1명.

유·불리를 정한 열은 **그 열의 `필수` 분산 항을 끈다**(`biasCols`). 안 끄면 둘이 싸워 기울기가
묻힌다. 진단표도 그 열은 기울인 목표로 재고 `조 크기` 라고 표시한다 — 비례로 재면 일부러
기울인 것이 어긋난 것처럼 보인다. 조마다 몇 명인지는 배정표 각 조 카드 위에 그대로 드러난다.

한 세션을 짜고 나면 **다른 세션을 다 알고 나서 각 세션을 두 번 더 다듬는다**.
순서대로만 짜면 뒤쪽 세션이 손해를 본다.

### 조건을 얼마나 세게 걸 것인가

세션마다 열별로 네 단계다.

- **무시** — 안 본다
- **보통** — 되면 좋고
- **중요** — 웬만하면
- **필수** — 새 사람 만나기보다 우선한다

해커톤 세션에서 개발경험을 **필수**로 두면, 개발 아는 사람이 조마다 고르게 앉는다.
**`같은 값끼리`** 로 뒤집으면 반대로 뭉친다(같은 언어권끼리 묶어야 할 때).

기본값(`autoDefaults`):

- **사전교육은 모든 세션에서 필수.** 교육을 안 받은 사람은 대개 일행으로 따라온 사람이다.
  일행 제약만으로는 갈라지지 않는다 — 서로 다른 일행에 속한 미수료자 둘은 한 조에 들 수 있다.
- **개발경험은 해커톤에서만 필수**, 조 크기 메우기까지 함께 붙는다.

사람이 한 번이라도 손댄 조건은 건드리지 않는다.

### 취침 방

방은 둘뿐이고 하룻밤을 되돌릴 수 없다. 그래서 세션보다 세게 건다.

- **이미 만난 사이는 늘 피한다** — 세션 만남 가중치(최대 10)가 아니라 `ROOM_MEET` 400 이다.
  따로 켤 것이 없다
- **같은 값이면 다른 방** — 소속·설계팀처럼 이미 아는 사이가 되는 열을 골라 켠다(`GUARD_PEN` 800).
  지킬 열은 **이름으로** 들고 있어 열 차례가 바뀌어도 살아 있다
- **사람이 고른 짝** — 몸짓은 셋 다 같다: 묶음을 만들고 이름을 누른다
  - `같은 방으로 묶기` 반드시 이대로. 성별을 따지지 않는다
  - `같은 방 안 됨` `AVOID_PEN` 3000 — 사실상 금지
  - `되도록 같은 방` `PREFER_BONUS` 1500 — 자동 규칙(만난 사이 400 + 같은 소속 800)을
    합친 것보다 크다. 사람이 직접 말한 희망이 우리 어림짐작에 밀리면 안 된다.
    성별과 `같은 방 안 됨` 은 여전히 이긴다

**방 번호는 직접 적는다.** 방 카드의 `1호` 를 눌러 `302호` 처럼 고치면 된다.
번호는 *자리*(몇 번째 방)에 붙으므로 다시 섞어도 그 방은 그 방이다.

지키지 못한 것은 **조용히 넘어가지 않는다**. 진단이 `같은 방인데 이미 만난 사이 N쌍`,
`되도록 같은 방을 못 지킨 짝 N쌍` 을 이름까지 적어 보여준다.

### 특정 사람을 특정 조에 못 박기

배정표에서 **이름을 누르면 그 조에 고정**된다(📌). 마음에 드는 자리가 나올 때까지 섞다가
눌러서 잠그는 흐름이다. 다시 누르면 풀리고, 세션 머리의 `고정 풀기` 로 한꺼번에 푼다.

못 박은 사람은 조의 앞자리에 앉히고 그 자리를 아예 교환 대상에서 뺀다(`anneal`) —
벌점으로 누르는 것이 아니라 구조적으로 안 움직인다. 나머지는 그대로 섞이고
일행·유불리 같은 다른 약속도 그대로 지켜진다.

사람이 빠지거나 조 개수가 줄면 걸린 고정은 `prunePins()` 가 걷어낸다.
**참석이 바뀔 때마다 돌아야 하므로 `recompute()` 안에서 부른다** — 붙여넣을 때만
부르면 불참 처리한 사람의 고정이 남는다.

### 내보내기

`결과 복사` 는 **배치만** 낸다. 일행·성별·조건 같은 속내도, 방을 묶은 것인지도 넣지 않는다 —
내보낸 표는 사람들에게 보여줄 것이라 필요한 것은 어디로 가는지뿐이다.

두 덩이가 빈 줄로 나뉘어 나온다:

1. **사람마다 어디로 가나** — `이름 · 세션1 · 세션2 · … · 숙박`
2. **세션마다 누가 모이나** — 세션 이름 아래 `1조 · 5명 · 가, 나, 다, 라, 마`, 그리고 숙박도 같은 꼴

### 진단

- **겹치지 않은 정도** — 같은 조에 앉은 자리 가운데 몇 %가 처음 만나는 사람이었나. 100%면 완벽
- **겹침** — 사람마다 (같은 조 자리 − 만난 사람). 0이면 그 사람은 한 번도 겹치지 않았다
- **만남 행렬** — 누가 누구를 몇 번 만났는지 한눈에

만난 사람 수가 사람마다 벌어졌다면 대개 **불참**이나 **조 크기** 탓이다.
그때는 `겹침` 을 보면 된다 — 그쪽이 배정을 탓할 수 있는 유일한 숫자다.

## 화면을 다루는 원칙

Jef Raskin 의 humane interface 를 따랐다.

- **모드가 없다** — 탭 대신 한 화면으로 흐른다. 왼쪽 레일은 지금 어디인지만 알려준다
- **저장 단추가 없다** — 바꾸는 즉시 남는다(localStorage)
- **계산 단추를 누를 필요가 없다** — 조건을 바꾸면 바로 다시 배정한다
- **확인 대화상자가 없다** — 대신 `Ctrl`+`Z` 로 되돌린다
- **한 가지 몸짓** — 이름을 누르면 그 자리에서 빠진다. 명단에서 누르면 워크샵 전체에서,
  세션 카드에서 누르면 그 세션에서
- **어디서나 붙여넣기** — 표를 붙이면 명단, 설정 JSON 을 붙이면 설정이 되살아난다
- **전체 다시 섞기** — 최상단. 확정한 세션은 건드리지 않고 나머지와 숙박을 새로 뽑는다

## 자주 있는 일

**사람이 갑자기 못 오게 됐다**
→ 명단에서 이름을 누른다. 남은 세션이 전부 다시 짜인다.

**한 세션에만 빠진다**
→ 그 세션 카드의 `이 세션 불참자 고르기` 에서 이름을 누른다.

**이미 진행한 세션은 그대로 두고 싶다**
→ 그 세션의 `확정`. 이후 배정은 확정된 만남을 알고 계산한다.

**부부/동료가 같은 방을 써야 한다**
→ 숙박의 `방 만들기` → 두 사람을 누른다. 강제 편성한 방은 성별을 따지지 않는다.

**명단을 고쳐 다시 붙여넣어야 한다**
→ 그대로 붙여넣으면 된다. 조건 설정은 **열 이름으로 이어받는다**.

**다른 기기로 옮기고 싶다**
→ `설정 복사` → 그 기기에서 `Ctrl`+`V`.

## 검사

고치면 반드시 둘 다 돌린다.

```bash
node check.js 6          # 배정 엔진 — 여섯 판을 돌려 규칙이 지켜졌는지 센다
node browser-check.js    # 진짜 브라우저 — 그려지는지·대비·속도·콘솔 오류
node browser-check.js --shot   # 그림도 남긴다
```

`check.js` 는 얇은 DOM 에 진짜 명단을 먹여 `recompute()` 를 끝까지 돌린다.
불러오기만 확인하는 검사로는 "선언 전에 쓴 변수" 같은 것을 못 잡는다.
`browser-check.js` 는 그리기를 본다 — 이쪽이 눈이다.

`check.js` 의 시간은 `vm` 샌드박스라 실제보다 대여섯 배 느리다.
**진짜 속도는 `browser-check.js` 를 본다** (30명·세션 4개 기준 280ms 안팎).

`browser-check.js` 는 이 상자에 깔린 크로미움(`/opt/pw-browsers/chromium`)을 쓴다.
없으면 playwright 가 알아서 찾는다.

## 되돌아오면 안 되는 버그들

| 증상 | 원인 |
|---|---|
| 명단을 붙여넣으면 스크립트가 죽음 | 세션이 생기기 전에 뜬 `oldAttr` 을 인덱스로 참조. 없을 수 있다 |
| "무시"가 켜진 것처럼 보임 | 4단 세그먼트의 0번도 강조색을 썼다. 0번은 조용해야 한다 |
| 다시 붙여넣으면 조건 설정이 날아감 | 조건을 열 *번호*로 들고 있었다. 열 *이름*으로 이어받을 것 |
| 배정이 굼뜸 | `Math.pow` 를 되풀이마다 부름. 온도는 곱셈으로 식힌다 |
| 숫자 열 머리와 값이 어긋나 보임 | `td` 만 오른쪽 정렬했다. `th` 도 같이 |
| 만남 행렬의 네 단계가 구분이 안 감 | 넷 다 옅은 톤(`*-soft`)이었다. 색조를 통째로 바꿀 것 |
| 불리한 사람이 큰 조에 다 몰림 | 선형으로만 밀었다. 기울인 목표를 이차로 걸 것 |
| 유·불리를 정했는데 안 먹힘 | 같은 열의 `필수` 분산(20)이 비례로 더 세게 당긴다. 그 열은 분산을 끌 것 |
| 유·불리를 정했는데 안 먹힘 ② | `wFair` 가 같은 조 크기를 반대로 밀고 있었다. 그 세션에선 끈다 |
| 일행이 같은 조에 섞임 | 열 이름이 `RE_PARTY` 에 안 걸려 역할이 `조건` 으로 잡혔다 |

| `O`/`X` 시트에서 유·불리가 안 붙음 | `있음/없음` 만 보고 있었다. 기호를 먼저 볼 것 (`biasGuess`) |
